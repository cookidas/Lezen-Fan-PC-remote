# LEZEN Tray 0.3.0

LEZEN LZEF-DC02를 Windows 작업표시줄의 알림 영역에서 조작하는 앱입니다. My LEZEN 1.3.8의 실제 송신 코드를 분석해 구현했습니다.

**Windows 송신 형식을 보정했고, LZEF-DC02 실물에서 전원 켜기·끄기와 200ms 켜기 송신의 정상 동작을 확인했습니다.** 등록·풍량·타이머·회전·모드에도 같은 보정을 적용했습니다. 전원 이외 기능의 실물 동작은 아직 개별 확인하지 않았습니다. 세부 기록은 `verification/debug-notes.md`에 있습니다.

이 사용자용 패키지는 휴대폰 원본 앱에서 확인한 코드 **6C3C**를 저장·선택해 두었습니다. 이 선풍기는 다시 등록할 필요 없이 바로 전원 메뉴를 사용할 수 있습니다. 이전 코드 D0BF는 기존 장치 목록 보존을 위해 남겨 두었습니다.

## 실행과 최초 등록

1. ZIP을 원하는 폴더에 전부 풀고 `app/LezenTray.exe`를 실행합니다. 이 PC에 설치된 .NET 9 Desktop Runtime을 사용하므로 별도 설치 없이 실행할 수 있습니다. 실행 파일만 다른 곳으로 옮기지 말고 `app` 폴더 전체를 보관하세요.
2. 저장된 장치가 있으면 바로 트레이에서 조작할 수 있습니다. 새 선풍기를 추가할 때는 `선풍기 추가 → 장치 추가 모드`를 엽니다. 이름을 입력하고 자동 생성된 네 자리 식별 코드를 사용합니다.
3. 등록할 선풍기의 전원 플러그를 뺐다가 다시 꽂습니다. **10분 이내**에 `등록 신호 보내기`를 누릅니다. 스마트폰 앱에 저장된 네 자리 코드를 알고 있다면 같은 코드를 직접 입력할 수도 있습니다.
4. 추가된 선풍기를 선택하고 `선택하고 닫기`를 누릅니다.
5. 시계 옆 선풍기 아이콘을 우클릭하고 `전원 · 미확인 → 켜기`를 눌러 실제 반응을 확인합니다. 아이콘이 안 보이면 숨겨진 아이콘 `∧`를 확인하세요. 아이콘을 더블클릭하면 장치 관리 창이 열립니다.

이 앱의 등록은 Windows 설정에서 하는 블루투스 페어링과 다릅니다. 원본 앱과 같은 등록 신호를 선풍기에 전송합니다. 다른 LEZEN 선풍기도 등록 대기 중이라면 시험할 선풍기만 전원을 연결해 등록하세요.

## 트레이 메뉴

| 항목 | 동작 |
| --- | --- |
| 전원 | 클릭할 때마다 켜기/끄기. 켜기 전송 후 초록색, 끄기 전송 후 빨간색 |
| 바람 강도 | `＋ 바람 세게` / `－ 바람 약하게` |
| 타이머 | `＋ 시간 늘리기` / `－ 시간 줄이기` |
| 좌우 회전 | 클릭할 때마다 회전 켜기/끄기 |
| 바람 모드 | 일반풍 / 자연풍 / 수면풍 / 온도모드 |
| 선풍기 추가 | 장치 추가 모드, 저장된 선풍기 선택, 이름 변경·제거·등록 재전송 |

**색상·회전·모드 표시는 마지막으로 전송한 명령 기준입니다.** 선풍기가 상태를 응답하는 통신은 원본 앱에서 확인되지 않았습니다. 리모컨·스마트폰으로 조작하거나 신호가 닿지 않으면 실제 상태와 다를 수 있습니다. 처음 실행했을 때 전원·회전은 `미확인`이며 첫 클릭은 켜기 명령입니다. 풍량과 남은 타이머 숫자는 수신할 수 없어 표시하지 않습니다.

설정은 `app/data/fans.json`에 저장합니다. 폴더를 옮길 때 이 파일도 함께 옮기세요. `목록에서 제거`는 PC 목록만 지우며 선풍기를 초기화하지 않습니다. 이전 검색용 개발 버전의 `devices.json`은 블루투스 주소 목록이라 새 등록 코드로 변환하지 않습니다.

## 문제를 확인할 때

먼저 등록 → 전원 켜기/끄기 → 풍량 → 회전 → 모드 → 타이머 순서로 확인하면 됩니다. 반응이 없다면 블루투스가 켜졌는지 확인하고, 선풍기 가까이에서 전원 플러그를 다시 꽂은 뒤 저장된 장치의 `등록 신호 다시 보내기`를 사용하세요. 계속 반응이 없으면 화면의 오류 문구와 반응한 기능을 알려주세요.

이 PC에서 전원 켜기·끄기의 실제 반응을 확인했습니다. 프로그램은 한 명령을 200ms 동안 광고하도록 요청합니다. 트레이의 `진단 로그 열기`로 Windows 송신 상태·시간·명령 데이터를 볼 수 있습니다. 로그는 `app/data/debug.log`에 저장하며, 큰 파일은 한 번 회전 보관합니다.

## 소스와 검증

대상: Windows 10 2004 이상 / Windows 11, .NET 9 Desktop Runtime. 빌드에는 .NET 9 SDK가 필요합니다.

```powershell
dotnet publish ./src/LezenTray.csproj -c Release -o ./app
dotnet ./app/LezenTray.dll --self-test ./menu-preview.png
dotnet ./app/LezenTray.dll --adapter
```

`--self-test`는 원본 ARM64 패킷 52개와 Windows 보정 패킷 52개, 실물에서 확인한 전원 패킷, 식별 코드 검사, 설정 직렬화, 메뉴 구성, 전원 색상·모드 표시를 검사합니다. 블루투스 신호를 보내지 않습니다. 미리보기의 장치와 상태는 시험용 예시입니다.

`src/packet-vectors.json`에는 4개 ID × 13개 명령의 기준 패킷이 있습니다. `verification`에는 원본 기계어를 실행하는 재현용 스크립트와 검증 기록이 있습니다. 원본 APK나 디컴파일한 앱 코드는 배포 파일에 포함하지 않았습니다. 분석 결과는 `APK-분석.md`에 정리했습니다.

진단용 `--send <네자리ID> <명령이름>`도 제공합니다. 이 옵션은 **실제 신호를 전송**하며 저장된 목록은 변경하지 않습니다. 예를 들어 `dotnet ./app/LezenTray.dll --send 1234 PowerOn`은 ID 1234에 켜기 명령을 보냅니다.

0.3.0의 기본 `--send`도 트레이와 같은 Windows 보정 경로를 사용합니다. 원본 비교용으로만 `--send <ID> <명령> 15 200 raw`를 사용할 수 있습니다. `--capture <파일.jsonl> <초>`는 My LEZEN 광고를 수신·기록하는 진단 옵션입니다.
